# End matter and retained rejection history

A final index can legitimately have source text but no narration. Generation
records a validated omission only when server-authored layout tags prove the
whole chapter is non-narrative and cleanup explicitly returns an omission.
An index heading alone, missing audio or empty edited text is insufficient.

The omission receipt uses the original pinned source and title, even when Gemini
changes the display title. Compilation and Audiobookshelf upload validate that
receipt and omit the chapter from audio assembly. The source manifest and chapter
indexes remain intact; no database or storage edits are needed for new valid
omissions. A changed source invalidates old evidence and requires review.

Retained rejection files are diagnostic history after a proven replacement.
Export requires both an authoritative chapter record and its audio object, plus
a recording receipt newer than the failure. A retained rejection marker also
requires matching failure content or a storage timestamp clearly preceding the
receipt. Storage times within the same second are treated conservatively.
Newer failures, missing receipts and unverified markers still block full export;
chapter uploads apply the same review check to the selected chapters. Diagnostic
files are preserved.

These changes do not reconstruct evidence for historical books or verify manual
database/storage repairs. A running installation must use the updated build.
